# Implementation Plan: Expand Lint Coverage with Neo4j Notification Codes

**Branch**: `007-expand-lint-notifications` | **Date**: 2026-05-10 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/007-expand-lint-notifications/spec.md`

## Summary

Add three new structural lint rules — `CartesianProduct` (03N90), `DeprecatedFunction` (01N01), and `DynamicProperty` (03N95) — that mirror statically-detectable Neo4j runtime notifications. Each rule populates the `code` field in diagnostics with its Neo4j notification code, requiring a small extension to the `Rule` struct and `.scm` file format to carry an optional `Code:` header.

## Rule Designs

### CartesianProduct (`03N90`)

```scheme
;; Rule: CartesianProduct
;; Severity: Warning
;; Applies-to: structural
;; Message: Disconnected MATCH patterns produce a cartesian product. Connect the patterns with a relationship or split into separate MATCH clauses.
;; Code: 03N90
(match_clause
  pattern: (pattern
    (path_pattern)
    (path_pattern) @hit))
```

Captures the *second* path_pattern in a multi-pattern MATCH. For three disconnected patterns, the third will also fire independently. Flag always at Warning per Neo4j's own INFORMATION level — the tool's conservative stance follows existing `UnlabelledNode` precedent.

### DeprecatedFunction (`01N01`)

```scheme
;; Rule: DeprecatedFunction
;; Severity: Warning
;; Applies-to: structural
;; Message: id() is deprecated in Neo4j 5. Use elementId() instead, which returns a stable string identifier.
;; Code: 01N01
(function_call
  name: (function_name
    . (identifier) @fn .)
  (#eq? @fn "id"))
```

The `. capture .` anchors require the `function_name` to contain exactly one identifier (excludes qualified names like `apoc.id()`). The `#eq?` predicate matches case-sensitively; `ID()` in all-caps is a separate concern for a follow-up.

### DynamicProperty (`03N95`)

Two match branches — parameter key and identifier key:

```scheme
;; Rule: DynamicProperty
;; Severity: Information
;; Applies-to: structural
;; Message: Dynamic property key prevents index use. Consider using a static property name if the key is known at query-write time.
;; Code: 03N95
(subscript_expression
  (expression)
  (expression
    [(parameter) (identifier)] @key))
```

The `[...]` alternation in tree-sitter queries matches either a `parameter` or `identifier` as the key. Integer and string literals are excluded — they are static keys and do not trigger the notification.
