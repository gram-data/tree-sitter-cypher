# Implementation Plan: Port openCypher BNF to Tree-sitter Grammar

**Branch**: `001-port-opencypher-bnf` | **Date**: 2026-04-29 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/001-port-opencypher-bnf/spec.md`

## Summary

Implement a complete Tree-sitter grammar for the openCypher query language by translating the 1,533-line BNF at `references/openCypher/grammar/openCypher.bnf` into `grammar.js` rules. Work proceeds in 8 independently-testable slices (P1–P8), each backed by corpus tests in `test/corpus/`, so the grammar is usable and shippable after every slice.

## Technical Context

**Language/Version**: JavaScript ES Module (grammar.js) + Generated C (parser.c via tree-sitter-cli)
**Primary Dependencies**: tree-sitter-cli ^0.26.5 (grammar generation), tree-sitter ^0.25.0 (testing/Node binding)
**Storage**: N/A
**Testing**: `tree-sitter test` (corpus tests in `test/corpus/*.txt`); `npm test` (Node.js binding smoke test)
**Target Platform**: Multi-platform via generated C parser; consumed by Node, Rust, Python, Go, Java, Swift, Zig bindings
**Project Type**: parser grammar library
**Performance Goals**: Parse a 100-line Cypher file in <50ms; incremental re-parse of one changed line in <5ms
**Constraints**: Generated parser has no external runtime dependencies; grammar.js is the sole hand-authored file
**Scale/Scope**: Full openCypher BNF — 12 top-level sections, ~200 named BNF productions
